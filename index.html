Lab Setup: Three-VM Network in VMware Workstation

You will build three virtual machines on a private network called Local, with pfSense acting as the router between Local and the internet. pfSense reaches the internet through VMware's built-in NAT adapter (the WAN). Nothing on Local uses DHCP: every address is typed in by hand.

All traffic from Windows and Ubuntu to the internet must pass through pfSense. That only works if their adapters are on Local, not NAT.

Before you begin

Build the VMs in this order: pfSense first, then Windows 10, then Ubuntu. You create the Local network while building pfSense, so it must exist before the other two.

Tip used throughout this lab: In each New Virtual Machine wizard, choose "I will install the operating system later." You attach the ISO afterward in Customize Hardware. This stops VMware's "Easy Install" from running on its own and skipping steps you need to see.

Part 1: Create the pfSense VM and the Local network

pfSense needs two network cards. The one VMware gives you by default is NAT, and it stays NAT: that is the WAN for the whole lab. You will add a second card for the LAN and connect it to a new LAN Segment named Local.

  1. In VMware, click File > New Virtual Machine. Choose Typical and click Next.
  2. Choose I will install the operating system later and click Next.
  3. Guest operating system: Other. Version: FreeBSD 14 64-bit (or the newest 64-bit FreeBSD in the list). Click Next.
  4. Name the VM pfSense and click Next.
  5. Set the disk size to 20 GB, choose Store virtual disk as a single file, and click Next.
  6. Click Customize Hardware.
  7. Set Memory to 2048 MB and Processors to 1.
  8. Select New CD/DVD. Choose Use ISO image file, click Browse, and pick the pfSense ISO on your desktop. Make sure Connect at power on is checked.
  9. Select Network Adapter. Leave it on NAT. This is your WAN. Do not change it.
  10. Click Add... at the bottom, choose Network Adapter, and click Finish. A second card named Network Adapter 2 appears in the list.
  11. Select Network Adapter 2 and choose LAN segment.
  12. Click the LAN Segments... button, click Add, type Local, and click OK.
  13. Back on Network Adapter 2, pick Local from the LAN segment dropdown.
  14. Click Close, then Finish.

Check yourself: the pfSense hardware list now shows two network adapters: Network Adapter = NAT and Network Adapter 2 = LAN Segment (Local). If you only see one, repeat steps 10 to 13.

Part 2: Install and configure pfSense

After this part, pfSense's LAN will be 10.0.0.1/24 with its DHCP server turned off.

  1. Select the pfSense VM and click Power on this virtual machine. Click inside the VM window to type in it (press Ctrl+Alt to release your mouse).
  2. Follow the installer and accept the defaults. If it asks which card is which, choose em0 for WAN (DHCP) and em1 for LAN.
  3. When the installer finishes, choose Reboot. If the installer starts over after the reboot, go to VM > Settings > CD/DVD, uncheck Connected, and restart the VM.
  4. pfSense boots to a text menu. Look at the top: WAN (em0) should show an address from VMware (usually 192.168.x.x), and LAN (em1) shows 192.168.1.1.
    • If WAN and LAN look swapped, type 1 (Assign Interfaces). Answer n to VLANs, enter em0 for WAN and em1 for LAN, then y to proceed.
  5. Type 2 (Set interface(s) IP address) and press Enter. Select 2 for LAN.
  6. Answer the prompts exactly as follows:
    PromptYour answer
    Configure IPv4 address LAN interface via DHCP?n
    Enter the new LAN IPv4 address10.0.0.1
    Enter the new LAN IPv4 subnet bit count24
    Upstream gateway for LANPress Enter (none)
    Configure IPv6 address via DHCP6?n, then press Enter for no IPv6 address
    Do you want to enable the DHCP server on LAN?n
    Do you want to revert to HTTP as the webConfigurator protocol?n
  7. Press Enter to return to the menu. Confirm the top now reads LAN (lan) -> em1 -> v4: 10.0.0.1/24.

Leave pfSense running for the rest of the lab. The other VMs cannot reach anything without it.

Part 3: Create and configure the Windows 10 VM

Reminder: VMware sets every new VM's network adapter to NAT by default. You must change the Windows adapter from NAT to the LAN Segment "Local" (step 5). If you skip this, Windows bypasses pfSense entirely.

  1. Click File > New Virtual Machine, choose Typical, then I will install the operating system later.
  2. Guest operating system: Microsoft Windows. Version: Windows 10 x64. Name the VM Windows10.
  3. Set the disk to 60 GB, single file. Click Customize Hardware.
  4. Set Memory to 4096 MB and Processors to 2. Under New CD/DVD, choose Use ISO image file and browse to the Windows 10 ISO. Check Connect at power on.
  5. Select Network Adapter. Change it from NAT to LAN segment and pick Local from the dropdown.
    NAT  to  LAN Segment: Local
  6. Click Close, then Finish.
  7. Power on the VM. When you see "Press any key to boot from CD or DVD," click inside the window and press a key right away.
  8. In Windows Setup:
    • Choose your language and click Install now.
    • Click I don't have a product key, select Windows 10 Pro, and accept the license.
    • Choose Custom: Install Windows only, select Drive 0 Unallocated Space, and click Next.
  9. After the restarts, Windows has no internet yet, which is expected. When asked to connect, choose I don't have internet, then Continue with limited setup. Create a local user name and password, and turn off the privacy options.
  10. Install VMware Tools: click VM > Install VMware Tools, open File Explorer, run setup64.exe from the DVD drive, accept the defaults, and restart.
  11. Set the static IP:
    • Press Windows+R, type ncpa.cpl, and press Enter.
    • Right-click Ethernet0 and choose Properties.
    • Select Internet Protocol Version 4 (TCP/IPv4) and click Properties.
    • Choose Use the following IP address and enter: IP address 10.0.0.10, subnet mask 255.255.255.0, default gateway 10.0.0.1.
    • Choose Use the following DNS server addresses and enter preferred DNS 8.8.8.8.
    • Click OK, then Close.

Part 4: Create and configure the Ubuntu VM

Reminder: just like Windows, the Ubuntu adapter starts on NAT. You must change it from NAT to the LAN Segment "Local" (step 4).

  1. Click File > New Virtual Machine, choose Typical, then I will install the operating system later.
  2. Guest operating system: Linux. Version: Ubuntu 64-bit. Name the VM Ubuntu. Set the disk to 25 GB, single file, and click Customize Hardware.
  3. Set Memory to 4096 MB and Processors to 2. Under New CD/DVD, choose Use ISO image file and browse to the Ubuntu ISO. Check Connect at power on.
  4. Select Network Adapter. Change it from NAT to LAN segment and pick Local from the dropdown.
    NAT  to  LAN Segment: Local
  5. Click Close, then Finish, and power on the VM.
  6. At the boot menu, choose Try or Install Ubuntu. In the installer:
    • Pick your language and keyboard.
    • On the network screen, choose Do not connect to the internet (you'll set the IP after install).
    • Choose Install Ubuntu, Interactive installation, and Default selection.
    • Choose Erase disk and install Ubuntu. This only erases the VM's virtual disk, not your computer.
    • Create your user name and password, pick your time zone, and click Install.
  7. When it finishes, click Restart now. If asked to remove the installation medium, press Enter.
  8. Log in and set the static IP:
    • Open Settings > Network. Next to Wired, click the gear icon.
    • Open the IPv4 tab and choose Manual.
    • Enter address 10.0.0.20, netmask 255.255.255.0, gateway 10.0.0.1.
    • Under DNS, turn Automatic off and enter 8.8.8.8.
    • Click Apply, then switch Wired off and back on so the new settings load.

Part 5: Test the network

All three VMs must be powered on. Each test should get replies unless noted.

FromCommandWhat it proves
Windows (Command Prompt)ping 10.0.0.1Windows reaches pfSense
Windowsping 10.0.0.20Windows reaches Ubuntu
Windowsping 8.8.8.8pfSense is routing to the internet
Windowsping google.comDNS lookups work
Ubuntu (Terminal)ping -c 4 10.0.0.1Ubuntu reaches pfSense
Ubuntuping -c 4 8.8.8.8pfSense is routing to the internet
Ubuntuping -c 4 google.comDNS lookups work

Expected failure: ping 10.0.0.10 from Ubuntu usually times out. Windows Firewall blocks incoming ping by default, so this does not mean your network is broken.

Log in to pfSense

  1. On the Windows VM, open a browser and go to https://10.0.0.1.
  2. At the certificate warning, click Advanced, then Continue. pfSense uses a self-signed certificate, so this warning is normal.
  3. Log in with user name admin and password pfsense.
  4. Click through the Setup Wizard. On the LAN page, keep 10.0.0.1 / 24.
  5. When the wizard asks for a new admin password, set one and write it down. Click Finish.
